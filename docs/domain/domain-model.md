# Domain discovery seed

This document starts domain discovery. It does not define a complete domain model.

The current product discovery recommends starting domain work with the evidence chain around a recurring player decision. See [product discovery](../product/product-discovery.md) for the product assumptions that motivate this focus.

## Strongly evidenced concepts

These concepts are intrinsic to the problem:

- Player
- Game
- Position
- Move
- Attempt
- Chess analysis evidence

## Likely but not yet settled concepts

- Learner Profile
- Weakness
- Strength
- Misconception
- Learning Goal
- Exercise
- Intervention
- Skill
- Mastery
- Progress

## Unresolved domain-modeling questions

- What counts as evidence for a pattern, and how should confidence change as evidence accumulates?
- Is a weakness a property of a player, a decision context, a task, or a time-bounded learner state?
- How should the model represent competing explanations for the same move?
- What evidence separates knowledge gaps from attention, time-management, or execution failures?
- How should learner state change after an exercise, a conversation, and a real-game result?
- Which claims must remain directly inspectable by the learner?
