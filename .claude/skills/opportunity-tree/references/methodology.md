# Opportunity Solution Tree methodology

Adapted from `lucasgaravelli/pm-skills-claude-code/.claude/commands/opportunity-tree.md` at commit `21cbb2903d740d10fc65c667aea97d3ee8657349` (MIT, Flowgrammers 2026), using the Opportunity Solution Tree method associated with Teresa Torres.

Use four conceptual levels: `desired outcome -> opportunities -> solutions -> experiments/learning tests`.

An opportunity is a customer problem, need, desire, or friction, not a feature. Evidence-backed opportunities cite sources; unsupported but useful branches remain explicit assumptions.

When using the upstream importance/satisfaction heuristic, calculate `score = importance * (1 - satisfaction / 5)` from declared inputs. Do not fabricate importance or satisfaction. Agent-estimated values are allowed only when clearly labeled estimates.

Explore multiple solution alternatives before commitment. For each, identify the riskiest assumption using value/usability/viability/feasibility categories and propose a cheap credible test. Prioritizing a branch remains agent judgment informed by outcome impact, evidence, uncertainty, and learning cost.
