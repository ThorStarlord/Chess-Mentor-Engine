# Roadmap

Satisfy a `product_strategy` responsibility by producing `roadmap`.

## Inputs

Require prioritized themes/initiatives, strategic goals, known dependencies, and any real timing/capacity constraints. Prefer `prioritized_list`, `strategy_doc`, and `okr_list` when available.

## Procedure

1. Read [references/contract.md](references/contract.md).
2. Group work into outcome-oriented themes/phases rather than a feature dump.
3. Sequence hard dependencies separately from desirable ordering.
4. Use dates/capacity only when supplied or explicitly estimated; label estimates.
5. Record expected outcomes and review triggers without claiming results.
6. Mark each initiative `proposed` unless durable authority supports a `committed` status.
7. Include buffers/contingencies only when justified by planning context rather than fabricated capacity.
8. Return `roadmap` and control.

## Boundary

`roadmap != promise`, `sequence != automatic execution`, `estimated date != commitment`, and `success criterion != observed success`.
