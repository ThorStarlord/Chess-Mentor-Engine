# OKR methodology and okr_list contract

**Methodological provenance:** adapted from `lucasgaravelli/pm-skills-claude-code@21cbb2903d740d10fc65c667aea97d3ee8657349`, `.claude/commands/okr.md`.

Retain useful principles: few objectives, clear ownership, outcome rather than output KRs, direct strategy alignment, measurable targets, and explicit review cadence. The upstream preferences for exactly three KRs, absolute numbers, and a 0.7 target score are heuristics rather than universal validator rules.

Produce sections: `## Strategy and cycle`, `## Objectives and key results`, `## Alignment`, `## Supporting initiatives`, `## Review cadence`, `## Uncertainties`, `## Machine-readable handoff`.

```yaml
artifact_id: okr_list
schema_version: "1"
status: proposed
cycle: "..."
strategy_refs: []
objectives:
  - id: OBJ-1
    statement: "..."
    owner_role: "..."
    aligns_to: []
    key_results:
      - id: KR-1
        measure: "..."
        result_type: outcome
        baseline: null
        baseline_status: unknown | observed
        baseline_evidence_refs: []
        target: "..."
        target_status: proposed
    initiatives: []
review_cadence: "..."
unresolved_questions: []
```

Objective/KR IDs are unique. KRs must use `result_type: outcome`; features/tasks belong under initiatives. An observed baseline requires evidence refs. Targets are `proposed` here and current achievement scores are not generated by this capability.
