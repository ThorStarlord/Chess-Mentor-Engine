# Persona

Satisfy a `customer_understanding` responsibility by producing a `persona_definition` artifact.

## Inputs

Require a product/context statement, target segment, and primary problem or job. Use any supplied customer, repository, market, or operational evidence. If primary evidence is absent, continue only as a provisional persona and say so explicitly.

## Procedure

1. Read [references/methodology.md](references/methodology.md).
2. Separate observed evidence, owner intent, and inference before synthesizing.
3. Build the persona around context, JTBD, pains, desired outcomes, current alternatives, behaviors, and decision constraints; avoid decorative demographic stereotypes.
4. Attach confidence and evidence references to material claims. Do not invent quotes; inferred voice examples must be labeled as inferred rather than represented as customer evidence.
5. Identify the highest-value research gaps created by low-confidence sections.
6. Render the artifact using [references/output-contract.md](references/output-contract.md).
7. Return control to the active agent. Do not select the next capability or claim the persona is market truth.

## Stop or downgrade

- Missing empirical evidence does not prevent a provisional persona; downgrade claim strength instead.
- If the user requires a validated/empirical persona and no customer evidence is available within current authority, stop with the evidence gap.
- If owner intent is necessary to choose among materially different target segments, surface that decision instead of inventing preference.
- Never conduct external customer outreach without separate authority.

## Boundary

A persona artifact is a decision aid. `artifact valid != persona true`, and `persona hypothesis != validated customer representation`.
